# FinPilot：中国市场智能投资研究与配置助手

FinPilot 是一个面向 AI 产品岗位求职展示、服务中国投资小白的 Streamlit 项目。它把原始 DDPG 资产配置原型升级为两条可以演示、解释和核验的用户旅程：

1. 资产配置：目标与风险问卷 → 金额方案 → ETF 产品示例 → 下跌模拟 → 保存与复查。
2. 公司研究：选择 A 股或港股公司 → 官方财报证据 → 核心矛盾 → 风险与验证条件 → 来源追溯。

项目不连接证券账户，不执行交易，也不把回测或研究状态包装成无条件买卖建议。

## 当前可演示能力

### 资产配置

- 将期限、亏损承受力、收入稳定性、流动性需求和下跌反应转为风险分数、现金底线、单类资产上限和目标波动。
- 默认配置 510300、159920、511260、518880 和现金，给出明确比例与参考金额。
- 支持风险适配、最小方差、最大夏普和等权配置四种方案比较。
- 前 65% 数据生成方案，后 35% 数据做样本外验证，并计入初始交易成本。
- 支持调整 A 股/港股内部比例，把暂不执行的资产转为现金。
- 支持静态市场下跌情景、降低风险、保存会话方案和下载 JSON 方案记录。
- 明确 90 天复查日期，以及目标、收入、风险或产品状态变化时的提前复查条件。

### 公司研究

当前内置两家公司真实官方证据包：

- 贵州茅台（600519）：2025 年报、2026 年一季报、2026 年半年报，来源为上海证券交易所。
- 腾讯控股（00700）：2025 年报、2026 年中报，来源为腾讯投资者关系网站。

研究页先展示研究状态、现在该做什么、四个关键数字和核心矛盾，再展示风险、验证条件与官方报告链接。当前结论分别为：

- 贵州茅台：等待盈利恢复。
- 腾讯控股：基本面通过，估值待补。

这些是基于已披露财务事实的研究状态，不是针对个人的证券买卖建议。

## 数据可信度设计

项目保留四类审计文件：

```text
data/evidence/
  Source_Index.csv                 来源、报告期、发布日期、URL 与页码
  Normalized_Financials_Long.csv   归一化长表财务数据
  QA_Flags.csv                     影响研究与估值可信度的未解决问题
  Validation_Checks.csv            实际执行的来源与数值核验
  filing_manifest.json             本地官方 PDF 的页数、大小与 SHA256
```

官方 PDF 只在本地审计时保留，不提交到 Git 仓库；应用运行依赖的是已核验、可追溯的轻量证据表，并提供官方原文链接。

当前明确保留以下缺口：

- 没有授权实时行情，因此研究卡不显示可执行的当前价格。
- 没有未来 12 个月一致预期，因此不伪造 NTM/FY1 动态市盈率、目标价或上涨空间。
- 没有授权财经新闻接口，事件层只使用公司、交易所和监管官方披露。
- 归一化包覆盖研究卡需要的关键财务指标，不是完整三张表或 DCF 模型输入包。
- 贵州茅台经营现金流受财务公司成员单位存款影响，页面不会把现金流同比大增直接解释为白酒主业改善。
- 腾讯 2026 年中期报告未经审计，页面会与经审计年报区别处理。

## 快速运行

Windows 用户可双击 `start_demo.bat`，也可以在 PowerShell 中运行：

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

浏览器打开：

```text
http://127.0.0.1:8501/
```

应用默认使用固定随机种子的离线演示数据，因此断网也能完成资产配置流程。在“研究工作底稿”中可以切换东方财富公开历史行情；请求失败会自动回退，不会无限加载。

## 测试

```powershell
python -m pytest -q
python -m compileall -q app.py advisor tests
```

测试覆盖风险规则、四类组合策略、样本外回测、中国市场证券映射、公开行情解析、动态估值边界、官方研究卡和证据来源完整性。

## 设计取舍

界面参考了成熟投顾和研究产品的共同模式：

- 先展示“现在做什么”，再展示证据和完整研究过程。
- 普通用户先看金额、产品、潜在损失与复查条件。
- 公式、回测指标、数据源接入状态和 QA 信息放入“研究工作底稿”。
- 所有结论区分已验证事实、公司口径、分析解释和缺失证据。
- 全站不依赖 Emoji 表达状态，使用清晰标题、颜色、文字和来源编号建立信任。

开源案例与产品参考拆解见 [docs/OPEN_SOURCE_REFERENCE_REVIEW.md](docs/OPEN_SOURCE_REFERENCE_REVIEW.md)。
