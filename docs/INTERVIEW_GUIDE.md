# FinPilot AI 求职讲解指南

## 一句话定位

我把一个无法直接复现、只关注组合收益的强化学习原型，重构成了一个可解释的多资产投顾 Agent：用户风险需求会转成配置约束，系统调用组合策略生成方案，再通过样本外回测和风险护栏决定方案能否进入展示或执行环节。

## 简历项目表述

**FinPilot AI｜可解释的多资产智能投顾 Agent（个人项目）**

- 围绕个人投资者“风险偏好难进入模型、策略收益难验证、配置结果难解释”的问题，设计风险测评、组合生成、样本外回测、风险校验和解释反馈的完整投顾链路。
- 将投资期限、亏损容忍度、收入稳定性、流动性需求与下跌反应转化为现金下限、单资产上限、目标波动和回撤阈值，实现用户画像到算法约束的可审计映射。
- 建立风险适配、最小方差、最大夏普和等权配置四类策略的统一评测框架，按时间划分训练/测试区间，并统一计算收益、波动、Sharpe、最大回撤、Calmar 和换手率。
- 设计回撤、集中度、样本长度和数据真实性护栏；使用确定性工具负责权重计算，Agent 负责流程编排与解释，避免语言模型直接进行高风险数值决策。
- 使用 Streamlit 搭建可交互 Demo，支持离线合成数据、公开历史行情和用户 CSV，保证断网场景下仍可完成现场演示。

以上表述只描述已经实现的功能，不写“提升收益”“降低回撤”等尚未经过统一实验验证的结果。

## 60 秒项目回答

**结论：** 这个项目不是简单展示一个收益曲线，而是验证 AI 投顾如何把用户约束、算法决策、历史证据和风险控制串成闭环。

**背景：** 旧版项目用 DDPG 输出资产权重，但缺少配置和数据，训练评估也没有严格时间隔离；同时，它不知道用户能承受多大回撤，结果也很难解释。

**个人动作：** 我重新定义了 Agent 的节点。第一步用五维问卷形成风险画像，并转成现金、集中度、目标波动和回撤约束；第二步调用四类组合策略；第三步只用前段数据拟合，在后段数据做样本外比较；最后让风险护栏判断是否超过用户承受范围，再生成引用真实计算结果的解释。

**验证：** 当前代码有自动化测试，并通过本地界面验证了离线、策略切换和在线历史数据链路。系统统一输出收益与风险指标，但没有把某次回测包装成业务结果。

**边界：** 目前是求职展示和研究原型，不构成投资建议；强化学习策略还没有接回统一评测，因此不会宣称 RL 优于传统方法。

## 高频追问

### 1. 为什么叫 Agent，不只是一个优化算法？

优化算法只负责“给定数据和约束求权重”。Agent 负责识别用户约束、选择工具、组织验证、触发风险规则和生成解释。每个节点都有明确输入输出，策略算法可以替换，但投顾决策链保持稳定。

### 2. 为什么不让大模型直接给配置比例？

资产权重必须满足和为 1、非负、现金下限和集中度上限。语言模型难以稳定满足数值约束，也不能保证复现。因此大模型适合做需求理解和解释，权重计算交给可测试的数值工具。

### 3. 为什么不用随机训练集和测试集？

金融数据有时间顺序。随机切分会把未来市场信息泄漏到训练过程。当前版本按时间使用前 65% 拟合、后 35% 测试，至少保证测试数据没有参与权重生成。

### 4. 为什么不能只看收益率？

投顾服务的是用户风险体验。同样的收益可能对应完全不同的波动和回撤。因此系统同时看年化波动、Sharpe、最大回撤和 Calmar，并把最大回撤与用户问卷阈值直接比较。

### 5. 产品上线后看什么指标？

第一层是链路健康：数据加载成功率、方案生成成功率、延迟和异常率；第二层是用户理解与决策：问卷完成率、解释展开率、预警查看率和预警后的方案调整率；第三层才是长期策略表现，并且必须按风险等级和市场阶段分组观察。

### 6. 强化学习下一步怎么接入？

先修正旧环境中的资金取整损失、最后一步奖励丢失和数据泄漏，再把 RL 作为第五种策略接入同一回测接口。使用多个随机种子和滚动时间窗口，与等权、最小方差和最大夏普做同口径比较；没有显著证据就不主张使用 RL。

## 不能写成既成事实的内容

- 不能声称策略稳定跑赢市场或传统基线。
- 不能把合成数据中的收益写成真实业绩。
- 不能声称已有真实用户、留存率或资产管理规模。
- 不能把回测通过表述成已可用于实盘交易。
- 不能声称已接入大模型或已完成强化学习 V2，除非后续代码和实验确实完成。
