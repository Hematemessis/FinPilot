# FinPilot AI 产品案例

## 1. 产品命题

多数资产配置 Demo 直接让用户选择一个算法，然后展示一条收益曲线。问题是：用户的风险需求没有真正进入决策，回测容易泄漏未来信息，模型给出的权重也缺少可核验解释。

FinPilot AI 的产品目标不是“预测明天涨跌”，而是把用户约束、组合算法、历史证据和风险校验编排成一个可审计的投顾决策流程。

## 2. 目标用户与场景

- 目标用户：希望做中长期多资产配置、但缺乏组合构建能力的个人投资者。
- 核心任务：根据期限、亏损承受力、收入稳定性和流动性需求，得到一套能解释风险来源的配置建议。
- 使用边界：辅助研究与投资教育，不替用户做证券交易，不保证收益。

## 3. Agent 工作流

| 节点 | 输入 | 输出 | 决策依据 |
|---|---|---|---|
| 数据校验 | 多资产价格序列 | 对齐、无缺失的价格矩阵 | 最少样本、日期唯一、价格为正 |
| 风险评估 | 五维用户问卷 | 风险分、风险等级、配置约束 | 期限、亏损容忍、收入、流动性、行为反应 |
| 策略生成 | 历史训练段、用户约束 | 现金及资产权重 | 最小方差、最大夏普、等权或风险适配 |
| 样本外验证 | 未参与拟合的后段数据 | 收益和风险指标 | 时间顺序切分、统一费用口径 |
| 风险护栏 | 回测结果、用户容忍度 | 通过、预警及证据边界 | 回撤、集中度、数据长度、数据真实性 |
| 决策解释 | 用户画像、权重、指标 | 结构化中文说明 | 结论、依据、指标、边界 |

## 4. 为什么暂不让大模型直接计算权重

投资组合权重属于数值决策。让语言模型直接生成百分比，难以保证约束满足、数值稳定和结果可复现。因此 V2 让 Agent 调用确定性的风险与优化工具，大模型未来只负责理解非结构化需求和生成基于真实计算结果的解释。

这是产品上的风险控制设计，不是简单地“有没有接入 LLM”。

## 5. 评测设计

### 策略效果指标

- 年化收益：描述长期收益速度。
- 年化波动：描述净值不确定性。
- 夏普比率：单位波动对应的超额收益。
- 最大回撤：历史最差峰谷损失，是用户风险体验的核心指标。
- Calmar 比率：年化收益相对最大回撤的效率。
- 换手率：连接策略收益与真实交易成本。

### 产品质量指标（下一阶段埋点）

- 问卷完成率与方案生成成功率。
- 风险预警触发率、用户查看率和调整方案率。
- 配置解释展开率与关键理由理解度。
- 数据加载成功率、方案生成延迟和异常率。

当前代码没有真实用户实验，因此不能把上述产品指标写成已取得结果。

## 6. 从旧版到 V2 的关键改造

| 旧版问题 | V2 处理 |
|---|---|
| 缺少配置、数据和依赖，无法直接运行 | 建立独立依赖与离线演示数据 |
| 训练与评估随机取自同一数据 | 按时间切分训练段与样本外测试段 |
| 奖励只看绝对金额变化 | 统一使用收益率、波动和回撤指标评估 |
| Markowitz 基线未接入 | 四种策略进入同一回测函数 |
| 没有用户风险约束 | 问卷结果落成现金与集中度约束 |
| 缺乏产品解释和合规边界 | 增加工作流轨迹、风险护栏和声明 |

## 7. 后续迭代

1. 加入滚动窗口与月度再平衡，避免单次拟合过度依赖某一历史阶段。
2. 接回修正后的 DDPG/PPO 策略，并与传统基线做同口径、多随机种子对比。
3. 增加压力测试：股债同跌、利率冲击和高波动情景。
4. 接入可选解释模型，但仅允许引用结构化计算结果。
5. 补充演示视频、架构图、真实截图和面试问答。
