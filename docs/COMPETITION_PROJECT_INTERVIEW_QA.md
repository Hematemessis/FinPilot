# 强化学习智能投顾项目面试题库

这份题库只按现有代码、比赛路演和简历写法整理。材料里没有出现的个人分工、实验参数和指标，不替你补写。

## 先改简历口径

目前这句话风险很高：

> 于全国人工智能应用创新大赛基于 RL（PPO/DDPG）与 LLM 设计智能投资顾问 Agent，实现年化 9.5% 收益与对话式交互

面试官很容易连续追问三件事：究竟跑的是 PPO 还是 DDPG，9.5% 如何年化，LLM 在代码里负责什么。现有材料不能完整回答。

建议先改成：

> 全国人工智能应用创新大赛｜智能投顾 Agent：参与设计“风险测评—股票池筛选—DDPG 动态配权—LLM 解释交互”流程，完成历史数据回测与对话式 Demo；围绕数据时效、决策偏差和合规风险提出改进方案。

只有在你能提供原始净值序列、起止日期、交易成本和可复现脚本后，再写具体收益率。

如果面试准备以后续重构的 FinPilot V2 为主，建议单独写成个人项目，不要与比赛版本混为一段：

> FinPilot AI｜可解释的多资产智能投顾 Agent：将旧版 DDPG 配权原型重构为“风险约束—组合生成—样本外回测—风险护栏—结果解释”链路，统一比较风险适配、最小方差、最大夏普和等权策略，并用自动化测试校验权重、回测和数据边界。

## 现有材料能证明什么

### 比赛方案层

- 方案包含板块分析、个股推荐和投资组合推荐。
- 用户问卷被映射为 C1 至 C5 风险偏好，再用于调整股票池范围。
- 路演将强化学习算法写成 PPO，状态包含资金、价格、持仓和基本面指标，动作被描述为买、卖、持有。
- 路演展示了 15 只股票的测试集回测曲线，但没有给出基准、交易成本、最大回撤、随机种子或年化公式。
- LLM 通过 API 和提示词完成新闻信息提取、情感分析、风险问答、组合说明和行业个股交互。

### 附件代码层

- 可执行训练入口实际创建的是 TF-Agents `DdpgAgent`，不是 PPO。
- 动作是“现金 + 三类资产”的非负连续权重，执行前会归一化，并不是离散的买、卖、持有。
- 环境每 5 分钟推进一步，奖励是相邻两步组合价值之差。
- 代码里有 Markowitz 策略类，但没有接进训练或统一评估流程。
- 附件缺少 `config.py`、行情文件、预处理脚本和依赖版本，无法按 README 直接复现。
- 这五个文件没有 LLM、新闻情感分析、风险问卷或对话页面代码。它们属于另一层产品实现。

### 指标层

- 简历中的“年化 9.5%”没有出现在代码和路演文字中。
- 路演图只能大致看出净值从约 100 万变化到约 114 万，不能据此确认 9.5% 年化收益。
- 因此，现阶段最稳妥的做法是删除 9.5%，或重新生成一份可复现的样本外回测报告。

## 90 秒项目介绍

下面这版可以直接说，但个人分工处必须换成真实内容。

> 这是我们参加全国人工智能应用创新大赛时做的智能投顾原型。我们想解决的问题是，普通用户很难把风险承受能力转成具体配置，传统投顾服务又很难做到低成本、持续交互。
>
> 整个方案分成三层。第一层是用户侧，通过问卷识别投资期限、亏损承受能力和风险偏好，并映射成不同风险等级的股票池。第二层是策略侧，用强化学习根据行情和持仓状态动态调整组合权重。现有训练代码实际采用 DDPG，因为配置比例是连续动作。第三层是交互侧，用 LLM 做风险问答、新闻信息提取和结果解释，但不让大模型直接计算权重。
>
> 我在团队里主要负责【数据处理 / 强化学习环境与回测 / LLM 交互 / 产品方案与路演，请保留真实部分】。项目最后完成了历史回测和对话式 Demo，也暴露出几个问题：PPT 与代码的算法版本不一致，回测缺少严格的时间外验证和成本口径，LLM 与数值模型的边界也需要更清楚。后来我把这些问题总结为可复现评测、风险护栏和确定性计算三条改进方向。

如果被要求 30 秒讲完：

> 我们做的是“用户风险画像 + 动态资产配置 + 对话解释”的投顾原型。问卷先确定风险等级，DDPG 根据行情输出连续配置权重，LLM 负责新闻提取和解释，不直接生成投资比例。我主要负责【真实分工】。项目完成了回测和交互 Demo，但原版本在数据隔离、风险指标和算法口径上不够严谨，这也是我后来重点重构的部分。

## 高频追问与答法

### 1. 你在项目里具体负责什么？

不要用“我们搭建了”代替个人动作。按下面四句话回答：

> 团队一共 3 人。整体方案包括数据、强化学习和对话交互。我个人主要负责【模块】；具体做了【两个动作】；交付物是【代码、接口、回测或页面】；另外两位同学分别负责【真实分工】。

面试前必须补齐：你写了哪些文件、调过哪些参数、做过什么实验、路演时由谁演示。现有材料不能替你证明这些内容。

### 2. 为什么用强化学习，而不是直接用均值方差或最大夏普？

> 我们当时选择强化学习，是因为资产配置是连续决策：今天的持仓会影响下一步可用资金和风险，目标也不只是某个时点的最优权重。RL 可以把这个过程建模为状态、动作和奖励的序列决策。不过这并不代表 RL 一定更好。严谨做法应该把它与等权、最小方差和最大夏普放在同一数据、成本和样本外区间里比较。原比赛版本没有完成这套统一评测，这是它的不足。

### 3. 你的代码到底是 PPO 还是 DDPG？

> 现有可执行代码是 DDPG，PPT 写 PPO 是版本管理没有统一，这个问题我会直接承认。我们要输出的是连续资产权重，DDPG 的 actor 可以直接给出连续动作，所以代码选择了 DDPG。简历不应该再写成 PPO/DDPG，除非我能拿出两套实现和同口径对比结果。

不要说“二者差不多”。PPO 是 on-policy，DDPG 是 off-policy actor-critic；二者的数据使用方式、稳定性和探索机制都不同。

### 4. 为什么连续配置权重适合 DDPG？

> 动作空间是现金和各资产的配置比例，每一维都在 0 到 1 之间，再归一化到总和为 1。若把每种组合离散化，动作数量会快速膨胀。DDPG 用 actor 直接输出连续动作，形式上更贴合权重配置。不过它对超参数和噪声较敏感，金融数据又非平稳，所以还需要多随机种子和滚动窗口验证。

### 5. 状态、动作和奖励分别是什么？

> 代码中的状态是三类资产经过标准化后的行情特征；动作是现金加三类资产的连续配置权重；奖励是本步组合价值减去上一步组合价值。环境每 5 分钟推进一次。

接着主动补一句：

> 这个奖励设计比较粗，只鼓励绝对收益，没有显式惩罚回撤、波动和换手，后续应该改成收益减风险与交易成本的组合目标。

### 6. 为什么奖励不用收益率，而用组合价值差？

> 原代码用了价值差，优点是直观，但它会受初始资金规模影响，不利于跨区间比较。更合理的做法是使用对数收益或相对收益，再加入换手成本和回撤惩罚，例如 `log(Vt/Vt-1) - λ1×turnover - λ2×drawdown_penalty`。权重需要通过样本外实验确定，不能凭感觉挑。

### 7. 你是怎么约束权重的？

> 原环境将 actor 输出限制在 0 到 1，再除以总和，因此只允许做多，现金和资产权重之和为 1。如果输出接近全零，则回退为等权。这个约束能避免负权重和杠杆，但没有单资产上限、行业集中度或最低现金比例，也没有按用户风险等级动态改变约束。

### 8. 用户风险问卷怎样真正影响模型？

> 比赛方案里，问卷主要把用户分成 C1 到 C5，并通过股票池波动率范围影响候选资产。问题是它没有直接进入强化学习环境的约束和奖励，因此“个性化”还比较浅。更完整的做法是把风险等级转换成现金下限、单资产上限、目标波动和最大回撤阈值，让这些条件参与权重求解和结果拦截。

### 9. 9.5% 年化收益是怎么算的？

现有材料下，最稳的回答是：

> 我复核后发现，现有交付物无法还原 9.5% 的年化过程，所以我不会继续把它当成已验证结果。严格计算需要保留起止净值、测试期交易日数、交易费用和现金流，公式是 `(期末净值/期初净值)^(252/测试交易日数)-1`。同时还要报告基准、最大回撤和 Sharpe。没有这些信息，单独说 9.5% 没有意义。

如果面试前找回原始结果，回答时必须一起说：测试期、样本内外切分、累计收益、年化收益、基准、最大回撤、Sharpe、交易成本和随机种子。

### 10. 路演曲线为什么不能直接证明策略有效？

> 一条净值曲线至少缺少四类证据：是否严格样本外、是否扣除成本、是否显著优于基准、结果对时间区间和随机种子是否稳定。路演还随机抽了 15 只股票，存在幸存者偏差和抽样偶然性。所以它只能说明链路跑通，不能证明策略稳定有效。

### 11. 训练集和测试集是怎么切的？有没有数据泄漏？

> 原代码从同一份数据里随机抽取片段创建训练和评估环境，而且标准化器在完整数据上拟合。这样可能让测试期分布进入特征处理，也不能保证真正的时间外验证。我会改成按时间切分，标准化器只在训练段拟合，再做 walk-forward 或 rolling-window 回测。

### 12. 交易成本、滑点和停牌怎么处理？

> 原代码没有完整建模交易成本和滑点，也没有处理涨跌停、停牌、最小交易单位等 A 股约束。它是研究原型，不是实盘系统。若进入可用版本，我会按成交金额计佣金和冲击成本，加入最小手数、不可交易状态和调仓频率限制，再观察扣费后的净收益和换手率。

### 13. 回测应该看哪些指标？

> 我会分三组。收益看累计收益和年化收益；风险看年化波动、最大回撤和回撤修复时间；风险调整后看 Sharpe 和 Calmar。还要看换手率、交易成本占比和不同市场阶段的表现。最终结论不能只由收益率决定。

### 14. 为什么代码里有 Markowitz，却没有比较结果？

> `policies.py` 里实现了一个随机组合筛选的 Markowitz 风格基线，但训练入口没有调用它，因此不能声称已经完成 RL 与 Markowitz 对比。后续需要把所有策略接入同一个回测接口，用相同资产、区间、费用和再平衡频率评估。

### 15. LLM 在这个系统中到底做什么？

> LLM 负责三件事：把用户问题转成结构化意图，从新闻中提取情绪或事件信息，把数值模型的结果解释成用户能理解的语言。它不直接计算权重，也不应该绕过风险规则。附件中的五个 RL 文件没有 LLM 代码，LLM 位于对话应用层，这两个实现要分开讲。

### 16. 新闻情感如何进入交易策略？

> 路演方案是先抓取个股新闻，再让 LLM 提取信息或做情感判断，作为个股筛选依据。现有材料没有证明情感分数已接入 DDPG 的状态或奖励，所以我不会说它已经驱动交易。若要真正接入，需要定义时间戳、来源可信度、重复新闻去重和可用时点，避免把盘后信息泄漏到盘中决策。

### 17. 为什么把它叫 Agent，而不是普通工作流？

> 严格来说，比赛版本更接近“固定流程 + LLM 对话”的投顾工作流。它按预设路径完成问卷、筛选、配权和解释，自治规划能力有限。若称为 Agent，我会把 Agent 定义为对工具的编排层：根据用户状态选择风险评估、行情分析、组合计算和解释工具，但数值计算仍由确定性模块完成。

这句比“用了大模型所以是 Agent”更稳。

### 18. 大模型幻觉怎么控制？

> 第一，LLM 只能引用工具返回的结构化字段，不能自行生成价格和比例。第二，所有权重、收益和风险指标由代码计算。第三，对新闻和研究结论保留来源、时间和置信度；证据不足时返回“无法判断”。第四，涉及买卖建议时增加合规提示和人工复核。

### 19. 这个项目最难的地方是什么？

按你的真实分工选一个角度，不要把全部困难都揽到自己身上。

算法角度：

> 最难的是把金融问题转成可训练环境。权重需要满足约束，奖励又不能只追收益。原版本先跑通了连续配权，但我后来意识到风险、成本和时间外验证才决定结果是否可信。

产品角度：

> 最难的是划清 LLM 与数值模型的边界。用户希望直接问“该买什么”，但系统不能让大模型凭语言生成权重。我们把 LLM 放在意图理解和解释层，把配置交给可复现模型。

数据角度：

> 最难的是可用时点。金融数据晚一分钟出现，就可能造成未来信息泄漏。需要同时记录事件发生时间、平台发布时间和策略实际可见时间。

### 20. 如果再做一次，你会先改什么？

> 我不会先调网络结构，而会先修评测。第一步固定资产池和时间切分，补齐成本、基准和风险指标；第二步修复环境中的资金取整、末步奖励和标准化泄漏；第三步把风险问卷转成可执行约束；最后再比较 DDPG、PPO 和传统策略。只有统一评测显示 RL 在某类市场阶段有稳定增益，才保留它。

### 21. 这个项目怎么上线？

> 数据层负责授权行情、公告和新闻；策略服务负责特征、权重和回测；Agent 层负责收集需求、调用工具和解释；最外层是权限、审计、风险拦截和人工复核。线上还要监控数据延迟、方案生成失败、权重越界、模型漂移和用户投诉。比赛版本只是原型，没有达到生产投顾要求。

### 22. 上线后你会看哪些产品指标？

> 先看链路是否可靠，包括数据成功率、方案生成成功率、延迟和异常率。再看用户是否理解并采取了合适动作，例如问卷完成率、解释展开率、风险提示查看率和提示后的调整率。长期表现要按风险等级和市场阶段分组观察，不能用一个总收益率评价所有用户。

## 面试官可能继续深挖的技术点

## 绝对不要说的几句话

- “PPO 和 DDPG 差不多，所以都写了。”
- “曲线最后涨了，所以年化大概 9.5%。”
- “LLM 会综合新闻，自动决定买卖。”
- “我们已经证明 RL 跑赢传统策略。”
- “这个 Agent 可以直接用于实盘。”
- “代码细节主要是队友写的，但我都了解。”

更可信的态度是：哪一层是方案，哪一层已经实现，哪一个数字可复现，哪一个问题后来才发现，都讲清楚。
